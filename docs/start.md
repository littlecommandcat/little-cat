# 功能文件撰寫指南

本文件用於說明如何為小喵喵的功能進行製作使用說明。

## 文件結構

每個系統都應建立獨立的Markdown文件。

文件名稱格式：`<system>.md`

例如：

* `音樂系捅.md`
* `安全系統.md`
* `歡迎系統.md`
* `misc.md`
* ...

其中`misc.md`用於放置無法歸類到特定系統的功能或說明。

## 系統文件

每個系統應該使用一個獨立的 `<system>.md` 文件。

文件內應說明該系統提供的功能、指令以及使用方式。

建議結構：
```md
# 系統名稱

簡單介紹這個系統的用途。

## 功能

列出此系統提供的主要功能。

## 指令

列出所有相關指令。

### 指令名稱

說明這個指令的用途。

使用方式：

/command

參數：

* `<parameter>`：必填參數
* `[parameter]`：選填參數

範例：

/command example

## 注意事項

補充使用此功能時需要注意的事項。

```

## 撰寫規則

文件內容應以使用者能夠理解為主要目標，不需要介紹程式碼的實作方式。

應優先說明：

1. 這個功能可以做什麼
2. 如何使用
3. 指令需要哪些參數
4. 參數是否為必填(括號表示)
5. 使用範例
6. 使用時的限制或注意事項(非必要)

避免加入與使用者無關的程式碼實作細節。

## 指令格式

指令應清楚標示名稱與參數。

例如：

### /help

可查看機器人擁有的指令及其介紹。

使用方式：

/help <command>

參數：

* `<command>`：要查看的指令

範例：

/help <音樂系統 播放音樂> 查看如何進行播放音樂

## 必填與選填參數

使用 `< >` 表示必填參數

使用 `[ ]` 表示選填參數

## 多個子指令

如果一個指令包含多個子指令應分別說明。

例如：

### /安全系統

安全系統頂層指令。

#### /安全系統 設置

設置使用者加入觸發各項主動防禦的安全系統

#### /安全系統 移除

取消使用主動防禦的安全系統

#### /安全系統 日誌頻道

設置主動防禦的安全系統的日誌頻道

#### /安全系統 掃描權限

掃描機器人可管理的成員數量

#### /安全系統 掃描黑名單

掃描所有成員是否在黑名單中


## 雜項功能

無法歸類到特定系統的功能應放在：

`misc.md`

例如：

* 機器人基本資訊
* 一般設定
* 非特定系統的指令
* 開發者相關指令(非必要)
* 其他零散功能

`misc.md` 的撰寫方式與其他系統文件相同。

## 新增系統

當機器人新增一個完整的功能系統時，建立新的：

`<system>.md`

例如新增「等級系統」：

`等級系統.md`

不要把不同系統的內容全部放在同一個文件中。

## 文件命名

文件名稱應使用簡短、容易理解的中文或英文系統名稱(英文使用小寫)。

如果功能無法分類，使用：

`misc.md`

## 文件目錄範例

docs/

├── start.md

|   ...

└── misc.md

`start.md` 是文件撰寫規範與入口說明。

其他 `.md` 文件則分別介紹對應的機器人系統。

## 最後檢查

新增或修改文件後，請確認：

* 文件名稱符合 `<system>.md` 格式
* 無法分類的內容放在 `misc.md`
* 指令名稱正確
* 必填參數使用 `< >`
* 選填參數使用 `[ ]`
* 每個功能都有基本使用說明
* 指令範例可以直接理解
* 系統之間的內容沒有混在一起
* 文件內容與目前機器人的實際功能一致
